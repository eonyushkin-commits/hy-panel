# hy-panel

VPN-панель в духе wg-easy: один статический бинарник (~9 МБ), JSON-файл вместо БД, без Docker. Ставится одной командой, а протоколы — Hysteria 2, AmneziaWG 3.1 и запасной TCP-канал VLESS + Reality (Xray) — устанавливаются и настраиваются в самой панели, окнами. Hysteria и Xray — официальные релизы: панель скачивает их с GitHub и сверяет SHA-256; сервер AmneziaWG (официальный amneziawg-go) встроен в панель. Пользователи общие на все протоколы, у каждого — галочки протоколов; mihomo получает блок на каждый протокол и общую группу fallback.

Требования: Linux amd64/arm64 с systemd; для AmneziaWG — `/dev/net/tun` (есть на любой обычной VM). Hysteria ≥ 2.4.4 (`/online` в trafficStats), Xray ≥ 25.3.6.

## Установка

На сервере, от root:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/eonyushkin-commits/hy-panel/main/install.sh)
```

Команда печатает адрес и пароль панели. Дальше всё в браузере: раздел «Протоколы» → «Установить» у нужных протоколов, см. [Протоколы в панели](#протоколы-в-панели).

Флаги передаются после скрипта: `bash <(curl …) -name AMS -host vpn.example.com`. Скрипт берёт бинарник под архитектуру сервера из последнего релиза, сверяет `SHA256SUMS` и запускает `hy-panel install`. Версию можно зафиксировать: `HY_PANEL_VERSION=v0.3.1 bash <(curl …)`.

`install` ничего не спрашивает: ставит панель и её агент, открывает порт панели в ufw и печатает адрес и пароль. Флаги: `-host` (адрес в ссылках клиентов, по умолчанию — публичный IP сервера), `-name` (префикс имён профилей), `-ui-port` (порт панели, по умолчанию 9443; `off` — только через SSH-туннель). Протоколы и пользователи — в панели.

Панель рассчитана на чистый сервер: протоколы ставит она сама. Если на сервере уже есть конфиг Hysteria или Xray, написанный не панелью, «Установить» на карточке протокола заменяет его своим (прежний сохраняется рядом с суффиксом `.bak-hy-panel`); пароли и клиенты из него не переносятся.

### Переустановка не ломает подключения

- **Повторный `install` — только обновление программы.** Пароль и адрес панели, пользователи, настройки протоколов остаются прежними — ссылки и QR клиентов тоже.
- **`hy-panel uninstall -y`** удаляет программу и службы панели; пользователи и настройки остаются (`/var/lib/hy-panel`, `/etc/hy-panel.env`). Пока панели нет, Hysteria не пускает новых клиентов (проверять пароли некому). Установил снова — всё как было, с прежними ссылками. Без `-y` команда только говорит, что сделает.
- **`hy-panel uninstall -purge -y`** удаляет и пользователей, пароль, адрес панели, конфиг AmneziaWG. Hysteria и Xray остаются установленными, но без панели никого не пускают; если не нужны — `systemctl disable --now hysteria-server xray`.
- Ссылки меняются только когда меняешь сам: настройки протокола в панели (порт, обфускация, сертификат, сайт для маскировки), «Новый ключ» или удаление пользователя. Установка нового протокола ссылки остальных не меняет: в подписке просто появляется ещё одна.
- **Если `install` оборвался** (обрыв SSH, ошибка systemctl), просто запусти его снова: он доделает то, что не успел. Ctrl+C и обрыв SSH во время записи файлов и перезапуска служб их не прерывают.
- Нечитаемый `/etc/hy-panel.env` (права, ошибка диска) не считается отсутствующим: `install` останавливается и ничего не пишет. Неверные значения в нём (порт, адрес, путь) тоже останавливают команду до записи.

### Протоколы в панели

Над списком пользователей — карточки протоколов: статус (не установлен / работает / остановлен), текущие настройки и кнопки. В шапке — адрес сервера и переключатель светлой и тёмной темы (пока его не трогали, тема как в системе; выбор запоминается в браузере).

- **Hysteria 2 → «Установить» / «Настройки»**: порт UDP (443, свой или диапазон 20000-50000 для port hopping), обфускация (salamander, gecko, без), сертификат (self-signed или свой домен через Let's Encrypt).
- **VLESS + Reality → «Установить»**: порт TCP и сайт для маскировки с кнопкой «Проверить» (TLS 1.3, HTTP/2, сертификат, та же ли подсеть /24) и кнопкой «Найти»: панель сама делает то, что обычно делают руками RealiTLScanner и проверочным скриптом, — обходит 254 соседних адреса сервера в его /24, собирает имена с сертификатов тех, кто отвечает по TLS 1.3 + X25519 + HTTP/2, и проверяет каждое имя: DNS указывает в ту же /24 (а не на CDN), сертификат действителен, `GET /` по HTTP/2 отдаёт 200. Лучшие (200, DNS на тот же адрес, быстрые) — сверху; выбранный подставляется и проверяется. Поиск занимает до минуты и уходит с сервера: 254 TLS-рукопожатия к соседям. Потом — «Настройки»: сменить сайт для маскировки.
- **AmneziaWG 3.1 → «Установить»**: порт UDP (по умолчанию случайный 51000–59999). Потом — «Настройки»: сменить порт.
- **Версия и «Обновить до …»** (Hysteria, Xray): агент несколько раз в день узнаёт последний официальный релиз (по перенаправлению GitHub `releases/latest`, без API). На карточке — «Версия 2.6.1 · последняя»; кнопка «Обновить до X» появляется, только когда вышла новая версия: скачать, проверить SHA-256, перезапустить службу. Если последнюю версию узнать не удалось, на карточке так и написано (причина — во всплывающей подсказке), а кнопка «Проверить обновления» спрашивает GitHub ещё раз. AmneziaWG обновляется вместе с панелью.

Установка и изменения идут в окне с живым логом. Панель скачивает релиз ([Hysteria](https://github.com/apernet/hysteria/releases): бинарник и `hashes.txt`; [Xray](https://github.com/XTLS/Xray-core/releases): zip и `.dgst`), сверяет SHA-256, ставит его так же, как официальные установщики (`/usr/local/bin`, служба `hysteria-server` от пользователя `hysteria`, `xray` от `xray`, geoip/geosite в `/usr/local/share/xray`), пишет конфиг и запускает службу. После изменения панель перезапускается сама; вход не сбрасывается.

Права. Сама панель работает от пользователя `hy-panel` в песочнице systemd и в систему не пишет. Всё, что требует root, делает служба `hy-panel-agent`: она слушает `/run/hy-panel/agent.sock` (доступ — root и группа `hy-panel`) и умеет ровно пять действий — настроить Hysteria, VLESS или AmneziaWG, обновить Hysteria или Xray. Каждое — это команда `hy-panel settings` / `xray` / `awg` / `fetch` с проверенными параметрами (числа, домены из списка допустимых символов, значения из перечня), без shell; одно действие за раз. Угаданный пароль панели даёт эти действия, но не root на сервере. Чтобы читать конфиг и сертификат Hysteria (`root:hysteria 0640`), у панели есть только `CAP_DAC_READ_SEARCH`.

Те же команды можно запустить и в терминале, только с флагами — вопросов они не задают: `hy-panel settings -port … -obfs … -cert … [-domain … -email …]` (неуказанное остаётся как было), `hy-panel xray -target сайт [-port 443]`, `hy-panel awg [-port …]`, `hy-panel fetch hysteria|xray`.

### AmneziaWG 3.1

WireGuard, который не узнаётся по виду пакетов: перед рукопожатием — мусорные пакеты и пакет-«подпись» (I1, здесь — DNS-запрос), сообщения дополнены случайными байтами (S1–S4), а с AWG 3 заголовки зашифрованы (`HeaderProtectionKey`) и к содержимому добавляется паддинг (`ContentPaddingAddition`). Профиль тот же, что ставят установщики AmneziaWG 3.1: H1–H4 = 1–4, S1–S4 ≥ 12 (из паддинга берётся nonce шифрования заголовков).

Сервер — официальный [amneziawg-go](https://github.com/amnezia-vpn/amneziawg-go), встроенный в панель (`hy-panel awg-serve`, служба `hy-panel-awg`): модуль ядра не нужен, работает на любом ядре. Интерфейс `awg0`, клиенты в сети 10.66.0.0/16, выход в интернет через NAT сервера (iptables, без него — nft; при включённом ufw панель разрешает маршрутизацию с `awg0`). В частные сети сервера (10/8, 172.16/12, 192.168/16, 100.64/10, 169.254/16) клиентов не пускает — как `geoip:private` у VLESS. Параметры сервера — `/etc/hy-panel/awg.json`.

Как и у Xray, своих клиентов у службы нет: раз в 10 с (и сразу после правки в панели) панель кладёт в неё ключи активных пользователей с включённым AmneziaWG. Выключенный, просроченный, исчерпавший лимит или удалённый пользователь убирается — и его сессия обрывается сразу. Трафик считается по счётчикам WireGuard, онлайн — рукопожатие за последние 3 минуты. «Новый ключ» меняет и ключ AmneziaWG.

У пользователя во вкладке AmneziaWG — конфиг `.conf` с QR и кнопкой «Скачать»: его берут AmneziaWG для Android, iOS, Windows, macOS (≥ 3.1) и Amnezia VPN (≥ 5.0.1.5). В подписку AmneziaWG не входит (у приложений нет для него ссылок в подписке), в mihomo — входит (`type: wireguard` с `amnezia-wg-option`, `version: 3`; проверено на mihomo 1.19.33).

### VLESS + Reality (Xray): запасной канал по TCP

Hysteria работает поверх UDP. Если UDP начнут резать, нужен канал по TCP, который снаружи выглядит как обычный HTTPS-сайт: VLESS + Reality + XHTTP на TCP 443 (с Hysteria на UDP 443 не конфликтует). Панель ведёт его пользователей так же, как пользователей Hysteria: у каждого две ссылки, подписка и сниппет mihomo отдают обе, лимит трафика, срок и «Новый ключ» общие.

Ставится в панели (карточка VLESS + Reality); Xray, если его нет, скачивается из официального релиза. Конфиг — `/usr/local/etc/xray/config.json`:

- **Установка** пишет новый конфиг: XHTTP на TCP 443 (или своём порту), новые ключи x25519, shortId и случайный путь, `api` на 127.0.0.1:10085 и статистика пользователей. Сайт для маскировки проверяется так, как подключается браузер: TLS 1.3, X25519, HTTP/2, действующий сертификат; в логе — в той же ли он /24, что и сервер. Конфиг, написанный не панелью, заменяется (прежний — в `config.json.bak-hy-panel`).
- **«Настройки»** меняют сайт для маскировки, если прежний перестал отвечать: ключи и порт прежние, клиенты с подпиской получат новый sni сами.

Новый конфиг проверяется `xray run -test` до перезапуска Xray; не прошёл — остаётся прежний.

Как это работает. У Xray нет внешней проверки паролей, как `auth.http` у Hysteria: кого он знает, того и пускает. Поэтому в его конфиге клиентов нет, а панель раз в 10 с через gRPC API Xray приводит список пользователей инбаунда к своим активным пользователям: добавляет новых и включённых, убирает выключенных, просроченных, исчерпавших лимит и удалённых, а после перезапуска Xray возвращает всех. Изменения в панели применяются сразу. Трафик (`QueryStats` со сбросом) и онлайн (`GetStatsOnline`, считается по IP клиентов) забираются в тот же цикл.

Раз в час панель проверяет, отвечает ли сайт для маскировки; два раза подряд нет — баннер в панели. Без живого сайта проверки ТСПУ получают ошибку вместо него, и сервер становится заметен. Сайт лучше брать обычный: домен, похожий на узел VPN-сервиса или хостинга (`nl-205.что-то.cloud`), заметнее.

Отпечаток TLS в ссылках, подписке и mihomo — Safari (`fp=safari`, `client-fingerprint: safari`), не Chrome. ClientHello Chrome несёт постквантовый ключ (X25519MLKEM768), весит ~1,7 КБ и уходит двумя TCP-сегментами (1288 + 444 байт). В части сетей второй сегмент время от времени теряется: Reality получает половину ClientHello, не может проверить ключ и отдаёт подключение настоящему сайту, а у клиента — таймаут на несколько минут во всех приложениях. ClientHello Safari помещается в один сегмент. Ссылки, импортированные до v0.3.0, несут `fp=chrome`: обнови подписку в приложении или импортируй ссылку заново (или смени «Отпечаток» на Safari вручную).

Протоколы (Hysteria 2, AmneziaWG, VLESS) включаются у каждого пользователя отдельно (галочки в его окне, по умолчанию — все). Выключенный протокол пропадает из его ссылок, подписки и mihomo; Hysteria такого пользователя не пускает и отключает, Xray его не знает. В списке у пользователя значки протоколов: зелёный — сейчас подключён, зачёркнутый — выключен.

Вкладка «Mihomo» в окне ссылок — полные конфиги и куски для своего конфига.

**Полный конфиг** — «Роутер (XKeen)» и «Компьютер (Clash Verge)», кнопка «Скачать .yaml». Это готовый конфиг mihomo с правилами (группы по сервисам, rule-providers; заблокированное — через VPN, остальное напрямую), в который панель подставляет прокси пользователя (`proxies`, в порядке Hysteria → AmneziaWG → VLESS: группы берут их через `include-all`) и первым правилом — сам сервер напрямую. Вариант для роутера — с портами XKeen (redir 5000, tproxy 5001, `routing-mark`) и панелью zashboard на :9090, `secret` у каждого пользователя свой и не меняется между скачиваниями. Вариант для компьютера — без них: порты и панель управления Clash Verge задаёт сам. Проверено `mihomo -t`.

Шаблон встроен в панель (`mihomo.yaml` в репозитории). Свои правила и домены — в своём шаблоне: положи его в `/etc/hy-panel/mihomo.yaml` на сервере, панель возьмёт его вместо встроенного (перезапуск не нужен). Панель меняет в нём только верхнеуровневые `proxies` (заменяет; если ключа нет — добавляет перед `proxy-groups`), `rules` (добавляет первую строку; нужен блочный список `rules:` + `  - …`) и `secret` / ключи роутера; комментарии и оформление остаются.

**Куски** — отдельный блок на каждый протокол пользователя и «Все + fallback» — его прокси и группа `fallback` в порядке Hysteria → AmneziaWG → VLESS: перестал работать протокол — mihomo сам перейдёт на следующий, пропал UDP вообще — на VLESS по TCP (проверено на mihomo 1.19.33, нужна поддержка XHTTP). Группа называется по `HYP_NAME`:

```yaml
proxy-groups:
  - name: "NL"
    type: fallback
    proxies: ["NL-router", "NL-router-awg", "NL-router-vless"]
    url: https://www.gstatic.com/generate_204
    interval: 120
```

`url` и `interval` — проверка, по которой fallback выбирает прокси: раз в 120 с mihomo через каждый прокси группы запрашивает `generate_204` (страница Google, отвечающая пустым ответом с кодом 204, специально для проверок связи). Ответил — прокси живой; трафик идёт через первый живой по порядку списка.

## Доступ

Как у 3x-ui: `install` печатает адрес вида `https://<IP>:9443/<случайный-путь>/` и пароль. Без пути панель отвечает 404, так её не находят сканеры. Сертификат свой, self-signed (`/var/lib/hy-panel/panel.{crt,key}`): браузер один раз предупредит, сверь SHA-256 из вывода и прими. `/auth` для Hysteria на публичный порт не выходит. Если ufw включён, порт откроется сам.

Управление на сервере:

```
hy-panel info          адрес, пароль, отпечаток сертификата
hy-panel passwd        новый пароль панели
hy-panel install       обновить (бинарник берётся тот, которым запущен)
hy-panel uninstall -y  удалить панель; пользователи и настройки сохранятся (-purge — удалить и их)
```

Другой порт — `install -ui-port 8443`. Только через SSH-туннель — `install -ui-port off` и `ssh -L 8090:127.0.0.1:8090 root@<IP>` → `http://localhost:8090`.

Подписки включаются отдельным портом, на нём есть только `/sub/<token>`. Клиентам на ядре Xray/sing-box подписка отдаёт ссылки, а Clash Verge и mihomo (`?format=mihomo` или User-Agent clash/mihomo) — полный конфиг для компьютера: импорт по ссылке, обновляется сам. `proxy-providers` на роутере тоже можно направить на неё: они берут из документа только `proxies`. В подписке лежат пароль и obfs-пароль клиента, поэтому отдавать её стоит по HTTPS с настоящим сертификатом: за reverse-proxy с TLS (Caddy, nginx) на своём домене. Строки в `/etc/hy-panel.env`, затем `systemctl restart hy-panel`:

```
HYP_SUB_LISTEN=127.0.0.1:2096
HYP_SUB_URL=https://vpn.example.com
```

Сертификат для адреса подписки нужен настоящий (например, Let's Encrypt): Hiddify, v2rayNG, v2rayN и mihomo скачивают подписку с обычной проверкой сертификата, и самоподписанный не примут. К самой Hysteria это не относится: её самоподписанный сертификат клиенты сверяют по отпечатку из ссылки, и подключение работает.

Без прокси, по открытому HTTP (`HYP_SUB_LISTEN=:2096`, ссылка `http://<host>:2096/sub/...`), подписка тоже работает, но пароли клиентов при каждом её обновлении видны всем по пути (провайдеру, DPI). Панель предупреждает об этом в баннере.

Комментарии — только отдельной строкой: systemd считает `# …` в конце строки частью значения.

По голому HTTP содержимое подписки (сервер, obfs-пароль, ключ) видно провайдеру и DPI. Без домена и TLS лучше раздавать QR и ссылки, а подписку не включать.

## Настройки панели

Все настройки панели — в одном файле `/etc/hy-panel.env` (права 0600); юнит запускает `hy-panel serve` без аргументов. Настройки Hysteria (порт, obfs, сертификат) живут только в её конфиге.

```
HYP_PASSWORD     пароль панели, ≥8 символов (hy-panel passwd)
HYP_UI_PATH      секретный путь панели
HYP_UI_PORT      порт HTTPS панели или off (только SSH-туннель)
HYP_HOST         IP или домен в ссылках
HYP_NAME         префикс профиля в клиентах
HYP_HY_CONFIG    конфиг Hysteria (/etc/hysteria/config.yaml)
HYP_HY_SERVICE   служба Hysteria (hysteria-server)
HYP_SUB_LISTEN   порт подписок (выкл)
HYP_SUB_URL      внешний адрес подписок
HYP_XRAY_CONFIG  конфиг Xray; есть — VLESS включён (пишет установка VLESS)
HYP_XRAY_SERVICE служба Xray (xray)
```

/auth для Hysteria всегда на `127.0.0.1:8090`. Если порт панели или подписки занят, панель продолжает работать (клиенты подключаются), а причина видна в панели.

## Поведение и ограничения

- Если панель лежит, новые подключения не авторизуются. Активные сессии продолжают работать. Юнит стоит с `Restart=always`.
- Конфиг Hysteria читается при старте; после изменений в панели она перезапускается сама. После ручной правки конфига — `systemctl restart hysteria-server hy-panel`.
- Самоподписанный сертификат: в ссылке `insecure=1` и отпечаток сертификата дважды — `pinSHA256` (официальный клиент, v2rayN, v2rayNG) и `pcs` (клиенты на ядре Xray, которые убрали `insecure`: v2RayTun, Happ). Hiddify отпечаток не проверяет и обходится `insecure=1`.
- Диапазон портов в ссылке: в адресе — первый порт, сам диапазон — в `mport` (так ссылку понимают и Xray-клиенты, v2RayTun / v2rayN). Mihomo получает `ports`.
- Счётчики трафика пишутся на диск раз в минуту и при остановке панели; изменения пользователей — сразу. При аварийном завершении панели (kill -9, сбой питания) теряется трафик максимум за минуту.
- Трафик забирается у Hysteria раз в 10 с запросом `/traffic?clear=1`, который сразу обнуляет её счётчики. Если Hysteria обнулила счётчики, а ответ до панели не дошёл (таймаут 5 с, перезапуск), трафик за эти 10 с не учтётся. Ошибка всегда в меньшую сторону: учёт может недосчитать, но не пересчитать. Если `/online` или `/kick` не ответили, лимиты и блокировки применяются на следующем цикле; новые подключения при этом проверяются как обычно.
- Kick срабатывает на следующем пакете сессии. Молчащая сессия заблокированного пользователя висит онлайн, но первый же её пакет её закроет. Если включить пользователя раньше, она закроется один раз, и клиент переподключится.
- Лимит устройств считает сессии по последней синхронизации (раз в 10 с); сверх лимита новое подключение отклоняется. После смены сети у телефона старая сессия держится до таймаута простоя (30 с), поэтому телефону ставь ≥2.
- Квота и срок проверяются при подключении и раз в 10 с: превышение возможно на объём трафика за 10 с.
- Имя пользователя служит ID в статистике Hysteria (и `email` в Xray), поэтому переименования нет.
- `users.json` — это вся база и бэкап, права 0600: в файле пароли и UUID VLESS.

VLESS (Xray):

- Конфиг Xray читается при старте панели; после изменений в панели она перезапускается сама. После ручной правки — `systemctl restart xray hy-panel`. Пока конфиг Xray не читается, панель не выдаёт ссылки и подписку (клиенты сохраняют рабочий профиль), а Hysteria работает как обычно.
- Заблокированный пользователь сразу убирается из Xray: новые соединения он не откроет, но уже открытые доживают до своего закрытия — kick, как у Hysteria, у Xray нет.
- Лимит устройств действует только на Hysteria: ограничить число подключений пользователя Xray не умеет. Онлайн VLESS — это число IP-адресов с открытыми соединениями.
- Пока панели нет, Xray держит переданных ему пользователей до своего перезапуска, после него — никого. `uninstall -purge -y` перезапускает Xray, и пользователей в нём не остаётся.
- Панель ведёт один инбаунд VLESS + Reality — тот, что написала сама (XHTTP). VLESS Encryption (`decryption` не `none`) и диапазон портов не поддерживаются.

## Сборка

CI (`.github/workflows/release.yml`) гоняет vet и тесты на push в `main` и на каждый PR. Релиз (бинарники `amd64`/`arm64` и `SHA256SUMS`) публикуется двумя способами:

- без git: Actions → build → Run workflow, ветка `main`, версия (например `v0.3.2`) — workflow сам создаст тег и релиз;
- push тега:

```bash
git tag v0.3.2 && git push origin v0.3.2
```

Релиз через Releases → Draft a new release не создавай: workflow тоже попытается его создать и упадёт.

Локально:

Go ≥ 1.25, без cgo:

```bash
go test -race ./...
CGO_ENABLED=0 GOARCH=amd64 go build -trimpath -ldflags="-s -w" -o hy-panel-linux-amd64 .
```

Файлы: `main.go` (команды, запуск), `server.go` (HTTP, API, вход, подписка), `proto.go` (протоколы: общий интерфейс ссылок и mihomo, список в порядке fallback), `sync.go` (/auth, синхронизация серверов протоколов: Hysteria, Xray, AmneziaWG; kick), `store.go` (пользователи, `users.json`), `hysteria.go` (чтение и правка конфига Hysteria, сертификаты, trafficStats), `xray.go` (чтение конфига Xray, ключи Reality, клиент gRPC API Xray), `xraysetup.go` (`hy-panel xray`: конфиг Xray), `links.go` (ссылки и mihomo Hysteria и VLESS), `mihomo.go` и `mihomo.yaml` (полный конфиг mihomo из шаблона), `agent.go` (root-помощник и его клиент), `fetch.go` (скачивание официальных релизов), `awg.go` (AmneziaWG: параметры, ключи, конфиги, mihomo), `awgserve.go` (служба AmneziaWG и `hy-panel awg`), `install.go` (install / uninstall / info / passwd), `settings.go` (`hy-panel settings`: конфиг Hysteria), `index.html` (UI, вшит в бинарник), `install.sh` (скачивание релиза).

E2E с настоящими Xray и mihomo (в CI не запускается): `XRAY_BIN=… MIHOMO_BIN=… go test -tags e2e -run E2E -v`.

`TestLinksGolden` сверяет всё, что получают клиенты (ссылки, подписки, mihomo, конфиги AmneziaWG, QR), с `testdata/links.golden`. Если ссылки меняются намеренно — `go test -run LinksGolden -update` и проверить дифф эталона.

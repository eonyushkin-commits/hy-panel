# hy-panel

Лёгкая VPN-панель для **Hysteria 2 и VLESS/Reality (Xray)**: один статический бинарник, JSON-файл вместо БД, без Docker. Панель устанавливает официальные серверы, проверяет SHA-256 релизов, управляет пользователями, считает трафик и выдаёт ссылки, QR-коды и подписки. Hysteria работает по UDP, VLESS — запасной канал по TCP.

Требования: Linux amd64/arm64 с systemd, Go ≥ 1.25 для сборки. Hysteria ≥ 2.4.4 для учёта подключений через `/online`, Xray ≥ 25.3.6.

## Установка

На сервере от root:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/eonyushkin-commits/hy-panel/main/install.sh)
```

Установщик печатает адрес и пароль панели. Открой панель и нажми «Установить» в строке нужного протокола. Для Hysteria выбери порт UDP, обфускацию и сертификат; для VLESS — порт TCP и сайт для маскировки. Затем создай пользователя и выдай ему ссылку или QR-код.

Флаги установки: `-host vpn.example.com` (адрес для клиентов), `-name AMS` (префикс профиля), `-ui-port 9443` (HTTPS-порт панели). По умолчанию адрес определяется автоматически. `-ui-port off` оставляет доступ через SSH-туннель:

```bash
ssh -L 8090:127.0.0.1:8090 root@<IP>
```

Панель доступна по `http://localhost:8090`. В обычном режиме браузер предупреждает о самоподписанном сертификате панели; отпечаток печатает установщик и `hy-panel info`.

Повторный `hy-panel install` обновляет программу и сохраняет пользователей, пароль панели, настройки Hysteria и ссылки клиентов. Если установка оборвалась, запусти её снова.

## Обновление и совместимость

Поддерживаются Hysteria 2 и VLESS/Reality. AmneziaWG не поддерживается.

Перед обновлением сохрани `/var/lib/hy-panel/users.json`, `/etc/hy-panel.env` и конфиг Hysteria.

База пользователей читается автоматически: пароли Hysteria, токены подписок, трафик, квоты, сроки и лимиты устройств сохраняются. Существующие UUID VLESS и ограничения `protoOff` для поддерживаемых протоколов сохраняются. Если версия только с Hysteria уже удалила UUID из базы, при первом запуске будут созданы и сохранены новые: старые ссылки VLESS потребуется заменить, Hysteria не меняется. Для восстановления прежних UUID можно использовать резервную копию базы. Поля ключей AmneziaWG больше не записываются.

Перед автоматической миграцией сохраняется исходный `users.json.pre-v2` с правами 0600. Миграция не запускается с новыми ключами, пока запись не завершится. Повреждённая база, пустые записи и повторяющиеся имена или ключи вызывают явную ошибку запуска, вместо молчаливой потери пользователей. Уже существующая резервная копия не перезаписывается.

После перехода на новый формат подписи сеансов потребуется один раз войти в панель заново. Дальнейшие перезапуски вход сохраняют; смена пароля и кнопка выхода завершают сеансы администратора во всех браузерах.

## Настройки Hysteria

На главной — три счётчика и компактная строка состояния каждого протокола с портом. Версия, параметры и время последнего успешного опроса находятся в «Настройках». При доступном обновлении кнопка появляется и в строке протокола. Если данные онлайна старше 30 секунд, панель показывает предупреждение. Онлайн считается по пользователям; детали отдельно показывают сессии Hysteria и IP-адреса VLESS.

- Порт UDP: 443, свой порт или диапазон 20000–50000 для port hopping.
- Обфускация: salamander, gecko или без обфускации. Доступность функций зависит от установленной версии Hysteria.
- Сертификат: самоподписанный или свой домен через Let's Encrypt.
- Обновления: агент проверяет официальный релиз несколько раз в день. Кнопка обновления появляется при новой версии; загрузка проверяется по SHA-256, затем служба перезапускается.

Изменения выполняются в окне с живым логом. После смены настроек Hysteria панель перезапускается сама, вход сохраняется. Если конфиг Hysteria написан не панелью, настройка заменяет его, сохраняя оригинал рядом с суффиксом `.bak-hy-panel`; старые пользователи из конфига не импортируются.

Конфиг и параметры панели заменяются через временные файлы. При ошибке записи, перезапуска или проверки готовности восстанавливаются предыдущие файлы и состояние служб; ошибка восстановления тоже попадает в лог. Конфиг Xray проверяется его командой `run -test` до замены рабочего файла. Этот откат рассчитан на обрабатываемые ошибки операции: отключение питания или принудительное завершение процесса между записями всё ещё требует проверки состояния.

Агент сохраняет состояние задания в `/var/lib/hy-panel-agent/job.json`. Если агент перезапустился во время операции, окно показывает прерывание. Самостоятельно повторять такое задание агент не будет.

Те же действия из терминала:

```bash
hy-panel settings -port 443 -obfs salamander -cert self
hy-panel settings -cert acme -domain vpn.example.com -email admin@example.com
hy-panel fetch hysteria
hy-panel fetch xray
hy-panel xray -target www.example.com -port 443
hy-panel info
hy-panel passwd
```

Неуказанные параметры `settings` сохраняют текущие значения. После ручной правки конфига перезапусти Hysteria и панель: `systemctl restart hysteria-server hy-panel`.

## Настройки VLESS/Reality

В строке VLESS нажми «Установить» или «Настройки»: порт TCP и сайт для маскировки. «Проверить» проверяет TLS 1.3 и HTTP/2, «Найти» ищет подходящие сайты в подсети /24 сервера. Xray устанавливается из официального релиза с проверкой SHA-256; панель создаёт ключи Reality и конфиг XHTTP. Прежний конфиг, написанный не панелью, сохраняется в `.bak-hy-panel` перед заменой. В конфиге лежит приватный ключ Reality, поэтому при каждой записи панель ставит ему права `root:<группа службы Xray> 0640`; группа берётся из юнита (`xray` у юнита панели, `nobody` — у официального установщика XTLS). Для юнита с `DynamicUser=yes` права не меняются.

Обновления Xray доступны из строки протокола и его настроек. После обновления панель перечитывает версию Xray и обновляет параметры клиентских профилей. После ручной правки конфига перезапусти `xray` и `hy-panel`. Если конфиг не читается, ссылки неисправного протокола не выдаются; исправный протокол остаётся доступен.

Параметры Reality зависят от поколения сервера: до Xray 26.9.9 используется классический ClientHello Safari, начиная с 26.9.9 — Chrome с X25519MLKEM768. Для нового сервера нужен актуальный клиент; интеграционные проверки выполнены с Mihomo 1.19.33. После перехода между поколениями обнови подписку или импортируй новые ссылки.

## Пользователи и клиенты

У пользователя есть пароль, UUID VLESS, переключатель доступа, выбор протоколов, общая квота трафика, срок действия, лимит сессий Hysteria, ежемесячный сброс и заметка. «Новый ключ» меняет пароль, UUID и токен подписки и закрывает старые сессии Hysteria. Имя используется как ID Hysteria и пользователя Xray, поэтому переименования нет.

Панель выдаёт `hysteria2://`, `vless://` и QR-коды для совместимых приложений, блок `proxies` Mihomo, полный конфиг для роутера с XKeen и для компьютера с Clash Verge. В подписке находятся разрешённые пользователю протоколы. Свой шаблон Mihomo можно положить в `/etc/hy-panel/mihomo.yaml`.

Самоподписанный сертификат передаётся с `insecure=1` и отпечатком в `pinSHA256` и `pcs`; Mihomo получает `fingerprint`. Диапазон портов передаётся в `mport`, в адресе ссылки стоит первый порт; Mihomo получает `ports`. Изменение порта, обфускации или сертификата меняет ссылки: подписка обновится сама, остальным клиентам нужно выдать новые ссылки.

## Подписки

Подписки включаются отдельным слушателем, доступен только `/sub/<token>`. Обычный ответ — ссылки в Base64, `?format=raw` — открытый текст. Для `?format=mihomo` или User-Agent clash/mihomo отдаётся полный конфиг для компьютера. Роутерный `proxy-providers` берёт из него список `proxies`.

Настройки в `/etc/hy-panel.env`, затем `systemctl restart hy-panel`:

```ini
HYP_SUB_LISTEN=127.0.0.1:2096
HYP_SUB_URL=https://vpn.example.com
```

На домене подписки настрой reverse-proxy с настоящим TLS-сертификатом, например Caddy или nginx. В подписке есть пароли; открытый HTTP передаёт их всем по пути. Сертификат HTTPS подписки проверяется обычным способом, самоподписанный сертификат Hysteria его не заменяет.

## Настройки панели и безопасность

Все настройки панели — в `/etc/hy-panel.env` с правами 0600:

```ini
HYP_PASSWORD=пароль-панели
HYP_UI_PATH=/секретный-путь/
HYP_UI_PORT=9443
HYP_HOST=vpn.example.com
HYP_NAME=VPN
HYP_HY_CONFIG=/etc/hysteria/config.yaml
HYP_HY_SERVICE=hysteria-server
```

При настройке VLESS панель добавляет `HYP_XRAY_CONFIG` (по умолчанию `/usr/local/etc/xray/config.json`) и `HYP_XRAY_SERVICE` (`xray`).

`HYP_PASSWORD` — не короче 8 символов; меняется через `hy-panel passwd`. Комментарии в env-файле ставь отдельной строкой.

Панель работает от пользователя `hy-panel` в песочнице systemd. Root-агент `hy-panel-agent` принимает команды через `/run/hy-panel/agent.sock`, доступный root и группе `hy-panel`. Разрешены настройка Hysteria, настройка VLESS/Reality и обновление каждого сервера, по одному действию за раз, с проверенными аргументами без shell. Для чтения конфигов и сертификатов панель имеет `CAP_DAC_READ_SEARCH`.

`/auth` доступен только на loopback `127.0.0.1:8090`, запросы с proxy-заголовками отклоняются. Hysteria запрещает клиентам через ACL доступ к loopback сервера и к частным сетям (10/8, 172.16/12, 192.168/16, 100.64/10, link-local с адресом метаданных облака 169.254.169.254, IPv6 fc00::/7 и fe80::/10), включая домены с такими IP; Xray закрывает их правилом `geoip:private`. На установленной панели правила обновляет повторный `hy-panel install`. Внешний ACL перед изменением сохраняется в `.bak-hy-panel`.

## Учёт и ограничения

- Hysteria проверяет пароль через панель при новом подключении: при остановленной панели новые подключения не проходят, активные сессии продолжают работать. Xray хранит разрешённых пользователей в памяти и продолжает принимать их до своего перезапуска; изменения доступа требуют работающей панели.
- Трафик читается каждые 10 секунд через `/traffic?clear=1`. Если ответ потерян после обнуления счётчиков Hysteria, эти данные недосчитаются.
- Квота и срок проверяются при подключении и каждые 10 секунд. Возможен перерасход за один цикл опроса.
- Лимит сессий применяется только к Hysteria и резервирует место при входе. Один клиент может открыть несколько сессий. При устаревшем снимке запрашивается `/online`; при ошибке вход с лимитом отклоняется. Онлайн VLESS — число IP-адресов с открытыми соединениями; ограничить число физических устройств Xray не умеет.
- Заблокированные, удалённые пользователи и старые UUID удаляются из Xray при синхронизации. Это запрещает новые соединения, но уже открытые могут завершиться позже: kick сессий, как у Hysteria, Xray не предоставляет.
- Kick закрывает сессию на её следующем пакете. Молчащая сессия может оставаться в онлайне до возобновления трафика.
- Трафик сохраняется раз в минуту и при штатной остановке. Аварийная остановка может потерять до минуты учёта. Изменения пользователей сохраняются сразу.
- Протоколы опрашиваются независимо. Сбой одного API не задерживает другой; исправный протокол остаётся доступен для экспорта. Пустая подписка вместо рабочего профиля не выдаётся.
- Сброс месяца выполняется перед добавлением очередного измерения, чтобы сохранить первый интервал нового месяца. Отрицательные значения трафика игнорируются, переполнение счётчика не отключает квоту.
- `users.json` содержит пароли, UUID и токены подписок: это база и резервная копия, храни её с правами 0600.

## Удаление

```bash
hy-panel uninstall -y
hy-panel uninstall -purge -y
```

Без `-purge` пользователи и настройки остаются, повторная установка восстанавливает доступ с прежними ссылками. С `-purge` удаляются данные и настройки панели, Xray перезапускается без пользователей. Серверы Hysteria и Xray остаются установленными. Без `-y` команда только описывает действие.

## Сборка и проверки

Ядро разделено на `internal/model` (пользователь и правила доступа), `internal/storage` (хранилище и миграции), `internal/atomicfile` (замена файлов), `internal/adminauth` (сеансы и ограничение попыток входа), `internal/transaction` (применение нескольких файлов с откатом), `internal/sitescan` (поиск соседних сайтов для Reality) и `internal/hostname` (проверка имён хостов). Протокольные адаптеры и HTTP-интерфейс используют эти модули через совместимые типы. Формат пользовательской базы остаётся JSON-массивом.

Тесты хранилища и сканера находятся рядом с кодом в `internal/storage` и `internal/sitescan`. Проверки HTTP-обработчиков и взаимодействия компонентов остаются в корневом пакете; `go test ./...` запускает тесты всех пакетов.

На Linux с Go ≥ 1.25:

```bash
go vet ./...
go test -race ./...
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags="-s -w" -o hy-panel-linux-amd64 .
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags="-s -w" -o hy-panel-linux-arm64 .
```

`TestLinksGolden` сверяет ссылки, подписки, конфиги Mihomo и QR с `testdata/links.golden`. При намеренном изменении клиентских форматов обнови эталон: `go test -run LinksGolden -update`, затем проверь diff. Тесты миграции проверяют чтение прежней базы и сохранение доступа Hysteria.

CI в `.github/workflows/release.yml` выполняет vet и тесты с race detector, собирает Linux amd64/arm64 и SHA256SUMS. Релиз запускается тегом `v*` или через Actions → build → Run workflow с номером версии.

`.github/workflows/verify.yml` проверяет Go 1.25 и текущий стабильный Go, реальные подключения Hysteria и VLESS/Reality (Xray 25.3.6 и 26.11.9), конфиги Mihomo и отдельный цикл systemd: установка, миграция, агент, откат настроек, обновление, смена пароля и переустановка. Бинарники протоколов закреплены по версиям и SHA-256. Этот workflow релизов не создаёт.

Для повторения в WSL: `scripts/check-linux.sh`, затем `scripts/check-protocols.sh <каталог-первой-проверки>`. Флаг `--systemd` дополнительно запускает проверку служб с sudo; она отказывается работать поверх существующей установки и удаляет созданные службы и тестовые данные. Эти проверки выполняй в тестовой Linux-системе.

Проверки интерфейса: `npm ci`, `npx playwright install chromium`, затем `npm run test:ui`. Node.js и Playwright нужны только для тестов, сборка панели от них не зависит. Для установленного Chromium можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Проверки протоколов сохраняют загрузки в `~/.cache/hy-panel/protocol-tools`; другой каталог задаётся через `HYP_PROTOCOL_CACHE`.
